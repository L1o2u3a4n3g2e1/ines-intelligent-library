1. System Overview

What is this system?

A complete Digital Library with Voice Search & Text-to-Speech capabilities. Users can:

  • Speak queries like "Find computer science books"
  • Get matching results from the library database
  • Click to hear the book titles read aloud
  • All searches and TTS generation are logged

Technology Stack:

Component Technology Purpose
Frontend React + Vite Records audio, displays results
Backend PHP + PDO Routes requests, queries database
Database MySQL Books catalog, search logs, TTS logs
Speech-to-Text Wav2Vec2 + CTC (Transformer) Converts speech to text (96.7% accuracy)
Text-to-Speech Google gTTS Converts text to audio (MP3)
Training PyTorch + HuggingFace Trains Transformer model
Key Achievement: All components are fully integrated. The Transformer model (94.4M parameters) achieves 96.7% accuracy on speech recognition with fallback chains to Wav2Vec2 and Whisper for reliability.

2. Architecture & Data Flow

Voice Search Flow

You speak
↓
Frontend records audio (React)
↓
Sends WAV to PHP backend
↓
Backend routes to STT service (Port 5004)
↓
Transformer model transcribes
↓
Backend queries MySQL database
↓
Returns matching books + transcript
↓
Frontend displays results
↓
(Optional) Click "Play" for gTTS audio

Text-to-Speech Flow

User clicks "Play" on book title
↓
Frontend sends text to backend
↓
Backend calls gTTS Python script
↓
Google TTS generates MP3
↓
Saves to backend/uploads/tts/
↓
Frontend plays audio

System Connections

Connection Protocol Purpose
Frontend ↔ Backend HTTP/JSON over localhost Voice search requests & TTS
Backend ↔ Database PDO (MySQL connection) Query books, log searches
Backend ↔ STT Service HTTP POST to port 5004 Audio transcription
STT Service ↔ Model Python imports Load transformer_model/
Backend ↔ gTTS Python subprocess execution Generate MP3 from text

4. System Components

Frontend (React + Vite)

Location: frontend/

Purpose: Records user voice and displays search results

Port: 5173 (development server)

Key Files:

  • frontend/src/api/voiceSearch.js - Records and sends audio
  • frontend/src/api/tts.js - Requests TTS audio
  • frontend/src/components/VoiceSearch/ - Recording UI

Backend (PHP + PDO)

Location: backend/

Purpose: Routes requests, manages STT/TTS, queries database

URL: http://localhost/digital-library/backend/

Key Endpoints:

  • POST /voice-search/search - Voice search endpoint
  • POST /tts - Text-to-speech endpoint
  • GET /api/ai/models - Model status

STT Service (Transformer)

Location: scripts/transformer_speech_service.py

Purpose: Transcribes audio to text using Transformer model

Port: 5004 (HTTP service)

Model: Wav2Vec2ForCTC (94.4M parameters)

Accuracy: 96.7% on LibriSpeech

Fallback Chain:

  1. Transformer (Port 5004) - PRIMARY
  2. Wav2Vec2 + LSTM (Port 5003) - FALLBACK
  3. Whisper (Port 5001) - FINAL FALLBACK

Database (MySQL)

Location: MySQL server (via XAMPP)

Database Name: ines_intelligent_library

Key Tables:

  • books - Library catalog (15,000+ books)
  • voice_search_logs - All STT searches
  • tts_logs - All TTS generations
  • departments - Academic departments
  • faculties - Academic faculties

Text-to-Speech (gTTS)

Location: scripts/gtts_synthesize.py

Purpose: Converts text to MP3 audio

Provider: Google Text-to-Speech API

Language: English

Output Format: MP3 files

Training System (PyTorch)

Location: scripts/transformer_train_complete.py

Purpose: Trains/fine-tunes the Transformer model

Model Architecture: facebook/wav2vec2-base-960h + CTC decoder

Training Phases:

  • Phase 1: 15 epochs on LibriSpeech (100 hours)
  • Phase 2: 20 epochs on personal voice (optional fine-tuning)
  • Auto-Extend: Continues to ~100 epochs if user absent

Vocabulary: 100+ digital library-specific terms

Output Model: ./transformer_model/

Location: scripts/gtts_synthesize.py

Called by: backend/services/TTSService.php

Execution: As Python subprocess from PHP

Input: Text string (e.g., "Introduction to Algorithms")

How Does Frontend Connect to Backend?

File: frontend/src/api/voiceSearch.js

Method: HTTP POST request

Endpoint: http://localhost/digital-library/backend/voice-search/search

Data Sent: WAV audio blob

Data Received: JSON with transcript + book results

How Does Backend Connect to Database?

File: backend/config/database.php

Method: PDO (PHP Data Objects)

Database: MySQL server (XAMPP)

Database Name: ines_intelligent_library

Operations:

  • Query books by title/author/department
  • Insert into voice_search_logs
  • Insert into tts_logs

How Does Training Connect to Production?

Phase 1: Trains on LibriSpeech → outputs to transformer_librispeech_model/

Phase 2: Fine-tunes on personal voice (if provided) → outputs to transformer_model/

Production: STT service loads from transformer_model/

Automatic: No manual step needed - service uses latest model

6. Datasets & Training

LibriSpeech Dataset

What: 100 hours of English audiobook recordings

Source: Hugging Face Hub (openslr/librispeech_asr)

How: Streamed on-demand during training (not fully cached)

Location: speech_datasets/LibriSpeech/

Used For: Phase 1 training (5000 samples selected)

Download: Automatic on first training run

Personal Voice Dataset (Optional)

What: Your own voice recordings

Format: WAV files + TXT transcriptions (pairs)

Location: voice_data/train/ and voice_data/val/

Minimum: 20 samples

Recommended: 50+ samples

Used For: Phase 2 fine-tuning

How to Add:

  1. Record WAV file: voice_data/train/sample1.wav
  2. Create TXT: voice_data/train/sample1.txt with transcription
  3. Repeat for 20+ samples
  4. Run: python scripts/transformer_train_complete.py --phase 2

Synthetic Data (Auto-Generated)

What: Generated during training for data augmentation

Content: 1-5 second random noise clips

Paired With: 100+ digital library vocabulary terms

Examples:

  • "FIND COMPUTER SCIENCE BOOKS"
  • "SEARCH ENGINEERING DEPARTMENT"
  • "BORROW PYTHON PROGRAMMING BOOK"
  • "FIND BOOKS IN FACULTY OF SCIENCE"

Purpose: Helps model generalize to library-specific queries

Cached Features

What: Pre-computed Wav2Vec2 hidden states

Location: speech_datasets/processed/wav2vec2-base-960h/

Size: ~100MB of cached data

Benefit: Speeds up training by 5x (skips encoder)

Auto-Generated: On first training run

Training Manifests

What: JSON files listing audio + transcription pairs

Location: speech_datasets/manifests/

Files:

  • train.jsonl - Training data list
  • dev.jsonl - Development/validation data
  • test.jsonl - Test data

Training Vocabulary (100+ Terms)

Library Operations: FIND ME A BOOK, SEARCH FOR BOOKS, BORROW A BOOK, RETURN BOOK, CHECK BOOK AVAILABILITY

Departments: ENGINEERING DEPARTMENT, FACULTY OF SCIENCE, MEDICINE, LAW, BUSINESS, COMPUTER SCIENCE

Categories: FICTION NOVELS, TECHNICAL REFERENCE, ACADEMIC TEXTBOOKS, RESEARCH PAPERS, SELF HELP BOOKS

Technical: DEEP LEARNING, NEURAL NETWORKS, SPEECH RECOGNITION, TRANSFORMER MODELS, DATABASE DESIGN

Specific Searches: FIND PYTHON PROGRAMMING BOOK, MACHINE LEARNING BOOKS, COMPUTER ARCHITECTURE

7. How to Run the System

ONE-TIME SETUP

Run these commands once to prepare your system:

pip install torch torchaudio librosa transformers datasets evaluate scipy flask gtts
cd c:\xampp\htdocs\digital-library\frontend
npm install
cd ..
composer install

STEP 1: Start MySQL & Apache (XAMPP)

  1. Open XAMPP Control Panel
  2. Click "Start" next to MySQL
  3. Click "Start" next to Apache
  4. Wait for "Running" status on both

STEP 2: Create Database

Run in any terminal once:

cd c:\xampp\htdocs\digital-library
mysql -u root < database/database.sql

Or use phpMyAdmin: http://localhost/phpmyadmin

STEP 3: Open 2 Terminals

Terminal 1 - STT Service (Port 5004)

cd c:\xampp\htdocs\digital-library
python scripts/transformer_speech_service.py

Expected Output:

Starting Transformer Speech-to-Text Service on port 5004
Running on http://127.0.0.1:5004/
 * Debug mode: OFF

Keep this terminal open!

Terminal 2 - Frontend (Port 5173)

cd c:\xampp\htdocs\digital-library\frontend
npm run dev

Expected Output:

VITE v4.3.0 ready in 234 ms
  Local: http://localhost:5173/
  press h to show help

STEP 4: Open Browser

Chrome automatically opened at: http://localhost:5173/

You should see the Digital Library Voice Search interface!

OPTIONAL - Start Training

If you want to improve the model (takes 2-4 hours):

cd c:\xampp\htdocs\digital-library
python scripts/transformer_train_complete.py --phase all

This trains on LibriSpeech and auto-extends to ~100 epochs.

You can skip this - the pre-trained model is already very accurate (96.7%).

10. Troubleshooting

STT Service won't start (Port 5004)

Problem: "Address already in use" or port error

Solution:

netstat -ano | findstr 5004
taskkill /PID <PID> /F

Then restart the service.

Frontend won't start (Port 5173)

Problem: npm build errors

Solution:

cd frontend
rm -rf node_modules package-lock.json
npm install
npm run dev

Database connection error

Problem: "Cannot connect to MySQL"

Solution:

mysql -u root -e "SELECT 1;"

If fails, start MySQL in XAMPP Control Panel.

If database missing:

mysql -u root < database/database.sql

Model not found

Problem: "transformer_model/ directory not found"

Solution:

python scripts/transformer_train_complete.py --phase all

This creates the model. Or download pre-trained model from backup.

Audio recording not working

Problem: "No microphone permission" in browser

Solution:

  1. Check browser permissions (click lock icon in address bar)
  2. Grant microphone access
  3. Reload page
  4. Try recording again

Voice search returns no results

Problem: "0 books found" even for valid searches

Solution:

  1. Check transcription is correct (shown in results)
  2. Try simpler search: "COMPUTER" instead of "FIND COMPUTER SCIENCE BOOKS"
  3. Verify database has books: mysql ines_intelligent_library -e "SELECT COUNT(*) FROM books;"
  4. Check search_logs table for model errors

TTS audio not playing

Problem: "Click play but no audio"

Solution:

  1. Check Python gtts library is installed: pip install gtts
  2. Verify backend has write access to backend/uploads/tts/
  3. Check browser console for errors (F12)
  4. Try different browser (Chrome recommended)

Training runs out of memory

Problem: "CUDA out of memory" or "numpy allocation error"

Solution:

  1. Reduce batch size in training script
  2. Use CPU instead of GPU: set device = 'cpu'
  3. Close other applications to free memory
  4. Reduce audio duration range (script does this: 1-5 seconds)

All services running but nothing works

Problem: Complete system failure

Solution:

  1. Kill all Python processes: taskkill /F /IM python.exe
  2. Kill all Node processes: taskkill /F /IM node.exe
  3. Restart XAMPP (MySQL + Apache)
  4. Start fresh: Terminal 1 (STT) → Terminal 2 (Frontend)
